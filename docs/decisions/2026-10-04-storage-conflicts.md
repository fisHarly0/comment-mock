# 多页面保存冲突

现状：五个 localStorage 分区直接覆盖写入，旧页面可无提示地覆盖其他页面的新内容；启动渲染还会写入重新生成 ID 的评论。

方案：记录各分区实际读取/成功写入的原始字符串作为基线。写入前比较浏览器当前值；storage、焦点与恢复可见时检查所有已读分区。发现差异后暂停该分区保存，本页编辑和完整 JSON 备份仍可用，不自动合并或替换内存。忽略无关键；删除和 clear 也视为变化。已确认的冲突持续到用户处理，不因再次编辑消失。

恢复：备份本页后，可确认载入浏览器已保存版本（刷新整页），或确认以本页覆盖冲突项。覆盖只授权确认前捕获的原值；确认过程中又发生变化的分区继续保护。普通重试不绕过冲突。读取损坏的保护与冲突独立，共用保存状态提示。

启动仅为不存在的评论分区保存示例；不重写已有数据。基线和冲突状态仅存于内存；五个存储键、JSON v2 与模板格式不变，旧版数据直接兼容。

边界：localStorage 比较和写入并非跨进程事务，此措施是乐观冲突检测，不是多人实时协作或原子锁。极短的同时写入窗口仍可能出现后写覆盖；storage 事件会提示与当前保存值不一致的页面，未写入的数据继续留在该页供备份。file URL 的跨页通知由浏览器决定，写入前比较仍有效；重点验证同源 HTTP 和当前 Chromium file 模式。
